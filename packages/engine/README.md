# @instinct/router-engine · 0.1.0

Backend-only pricing engine extracted from the router test lab, independent of the Instinct application and any test wallet.

`createQuoteService({providerKeys, auroraPolicy, chainTiming, independentRoutes, debridgeRoutes, fetch, now})` returns `config`, `resolveAsset`, `quote`, and `inspectExecution`. Wallet addresses are mandatory caller inputs. Provider keys and fee/timing policy are trusted server configuration; they are never accepted from public quote requests.

`quote(input,signal,onCandidate)` optionally reports validated public candidates as each path arrives. The callback receives the same projection as final results, with eligibility evaluated at arrival; no early winner is selected. `debridgeRoutes: true` opts into public DLN estimates for the original cross-chain pair. The provider is excluded from independent-only scope and same-chain swaps, retains unknown costs and cannot win ranking. Commercial DLN access requires a separate credential integration.

The base registry configures Base, Solana, Ethereum and Arbitrum. The host can pass `additionalChains` and `additionalAssets` from `await discoverQuoteCatalog({providerKeys})` to include enabled provider-supported EVM chains for pricing, using explicit protocol identifiers and native-token metadata. The local launcher does this at startup; catalogs never enable execution or import RPC URLs/contracts. Unknown chain timing stays unknown. Relay quotes, Aurora dry previews, and Base/Solana native-USDC CCTP protocol pricing are supported subject to exact asset binding, liquidity, and evidence. Solana mint lookup checks finalized mainnet metadata. Custom EVM contract lookup uses exact chain/address matches and reports `PROVIDER_CATALOG` provenance. Preset tokens are suggestions; unsupported EVM metadata can use caller-entered decimals for previews. Token decimals support the uint8 range, 0–255. Unknown full costs never become zero or win ranking.

The trusted option `independentRoutes: true` registers Raydium swaps on Solana, direct Uniswap V3 pool simulations on Base and native-USDC CCTP intermediates. Public requests can set `routeScope: 'INDEPENDENT'` to exclude Relay/Aurora, or `ALL` (default) to compare available families. The option is disabled by default and fails closed when requested on an unconfigured server. Public callers cannot supply endpoints or contracts. Composed candidate `steps` expose exact assets, conservative amounts, conditional pricing and the requirement to reprice after settlement. Unknown costs prevent these previews from winning ranking.

The quote service is read-only and never returns signing artifacts. Completion estimates are configured and unmeasured; service/provider RTT values are measured. See the root README for precise provider and asset-class coverage.

`inspectExecution({source,destination,amount,sender,recipient,slippageBps?})` is an opt-in read-only Base ETH→USDC check. It constructs canonical native-input Uniswap calldata internally, simulates the actual sender, checks balance, estimates all native fee components and rechecks the canonical block. Public reports deliberately omit the transaction. `READY_FOR_REVIEW` is not permission to execute; cost estimates and state expire within seconds. Contract/delegated-code senders are unsupported.

`createExecutionEngine({executionPins,rpcEndpoints?,providerKeys?,fetch?,now?})` separately exposes `prepare`, trusted `recipes`, fresh-action `verifier`, and exact `capabilities`. It supports Base native ETH18→canonical Base USDC6 with reviewed token/router/factory/oracle pins, plus a separately pinned Relay Base native ETH18→canonical Solana USDC6 lane. The host supplies wallet authentication and durable coordination using the server package. It never signs, broadcasts, or imports wallet secrets. Source input, destination recipient/floor, gas bounds and deadline are locally reconstructed; claim validates the unchanged action again. Receipt verification requires its exact transaction, canonical block transaction membership, historical code/implementation pins, at least 12 Base confirmations and same-transaction USDC credit from the reviewed pool. Finality depends on trusted RPC observations; 12 L2 confirmations are not Ethereum finality.

Trusted `rpcEndpoints.base` accepts up to three HTTPS read endpoints and defaults to dRPC then Base's public RPC. Eligible transport failures restart the complete check, never mixing endpoint evidence. Public callers cannot supply RPC URLs or contracts. Native fee reserves are estimates, including L1/operator components; the receipt records verified actual fees. Staged CCTP mint reviews and broader cross-chain recipes remain separate blockers. Live simulation success is not proof that a user-signed on-chain trade has completed.

The additional recipe `relay-base-native-solana-usdc-v1` admits only Base native ETH on `eip155:8453` to USDC mint `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` (6 decimals) on `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`. It requires explicit depository bytecode/owner/allocator, Base solver, Base fee-oracle implementation and Solana solver-signer pins. Provider calldata is compared with locally reconstructed depository ABI and exact committed order terms. Known fees, impact/slippage checks, plain EOA funding and native balance simulation remain required. Explicit null fee/native policies remove only caller ceilings; finite reviewed gas reserves and numeric limits remain enforced. Relay reviews last at most 60 seconds, shortened by the provider order deadline; fresh preparation must finish within its separate 15-second pricing window, and the source contract may not enforce the UI cutoff.

One source-wallet EVM approval funds the lane; the recipient's Solana wallet never signs. Source confirmation verifies the original Base funding action and deposit event. A separate destination verifier checks finalized Solana genesis/status/block membership, USDC recipient balance increase and solver-authorized payout with a pinned signer's order-ID memo. `destinationReceipt` binds request/order evidence to the source hash; provider status alone is insufficient. This introduces explicit Relay solver and trusted-RPC assumptions, not a trustless bridge certificate. The host journal rejects funding, order and payout replay and preserves source-only pending recovery. Reverse Solana and other providers remain blocked by exact engine `supportedRoutes`. Quote/preflight checks, historical finalized payout evidence and mocked lifecycle checks are not a completed live user trade.

Trusted configuration adds `executionPins.relay = {depository:{codeSha256,owner,allocator},solver,solanaSolverSigners:[publicKey]}` alongside existing `executionPins.base` pins. Each value must be independently reviewed; omitted pins keep the lane disabled. Operator-only `rpcEndpoints.solana` accepts a reviewed HTTPS endpoint list (default Solana mainnet-beta); callers cannot select RPCs. The Relay recipe review cap is 60 seconds, with pricing capped at 15 seconds and provider expiry applied as an additional bound, within the lifecycle's 90-second maximum.
