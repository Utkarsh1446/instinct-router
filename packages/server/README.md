# @instinct/router-server · 0.1.0

Node HTTP API for standalone pricing and opt-in user-wallet execution. `createRouterApi({service, apps, execution?:{engine,store}})` returns an unstarted server. Execution requires a trusted configured engine and durable store; supported routes are Base native ETH → canonical Base USDC and pinned Relay Base native ETH or USDC → canonical Solana USDC. Deploy behind your own reviewed HTTPS ingress.

Apps have separate publishable browser keys and secret server Bearer keys. Exact origins, bounded requests, app/global quotas, cancellation, strict JSON/header handling, owned quote snapshots, and quote idempotency are enforced. App authentication is not wallet ownership or financial consent.

Connections support five-second keep-alive reuse. App body readers share the app's concurrency limit, in addition to the global body bound. Rolling-window rate errors include the actual remaining retry delay. Monotonic operation deadlines reject late engine results even if the timeout callback is delayed; actual transport settlement releases capacity.

`/healthz` reports liveness. `/v1/config`, `/v1/capabilities`, `/v1/assets/resolve`, `/v1/quotes`, and owned `/v1/quotes/:quoteId` provide pricing. `/v1/executions/inspect` provides fresh read-only Base wallet/simulation/fee evidence without a transaction artifact. It uses the same app isolation, body limits, quota and timeout controls; inspection results are not snapshotted or replayed. `/v1/executions/prepare` accepts a fresh exact request plus explicit native fee budgets, with no silent conversion of pricing snapshots into authority. Unsupported routes or an unconfigured execution engine remain unavailable. See the [execution protocol](EXECUTION_API.md) for exact schemas.

Pricing snapshots/replay entries are bounded and process-local, disappear on restart, and are separate from the durable execution journal. Live replay keys are preserved under cache pressure; expired keys may be evicted and forgotten. The root OpenAPI contract and README document configuration and limits.

`POST /v1/quotes/stream` uses the same strict input, app isolation and quotas with NDJSON START/CANDIDATE/COMPLETE/ERROR events. Candidates are provisional; COMPLETE contains the ordinary saved quote snapshot. Streams reject idempotency keys. Limits include 128 candidates, 256 KiB per line, 2 MiB total, a 64-event queue, two-second drain timeout and an absolute delivery deadline of quoteTimeoutMs plus two seconds. Disconnect/slow-reader failure cancels work and may close without a terminal event; clients must reject incomplete streams. Service-work quota remains reserved until the actual service promise settles, while the core scheduler separately bounds underlying provider transports that ignore cancellation.

Execution additionally requires an app/origin/chain/address-bound wallet-control token. EVM proof uses EIP191 through pinned `viem` 2.56.3; Solana proof uses Ed25519. Message proof is distinct from approving a trade. Tokens are memory-only and expire after fifteen minutes; restart requires fresh proof without discarding durable execution records.

`POST /v1/executions/:id/watch` with `{}` streams authenticated NDJSON status updates. The example uses this connection immediately after recording the wallet transaction. Source and independently verified delivery progress are flushed without another browser request; final completion remains a separate state. Checks target 250 ms between starts, never overlap, and yield at least 25 ms after a slower proof. The stream has separate app/global connection quotas, one connection per app/wallet/execution, and every check retains the ordinary work quota. It revalidates the wallet session before reads and before sending results. Limits: 120 seconds, 1024 frames, 256 KiB per line, 8 MiB total, eight queued events and one second to drain a blocked write. Reconnect/Resume always follows the original hash; stopping status checks does not stop a transaction.

Configure ingress to forward `application/x-ndjson` without response buffering or compression buffering, and allow a connection idle/read timeout exceeding 123 seconds. The API emits `X-Accel-Buffering: no` and flushes each frame; an intermediary must preserve streaming. Measure detection-to-send, receipt-to-display, and chain-inclusion-to-display separately. Provider indexing/RPC latency, network latency, clock alignment and background-tab scheduling prevent a universal one-second guarantee. Current improvements have offline validation only.

Prepare saves immutable reviewed terms and action digests, with a maximum 90-second review lifetime. Claim rechecks fresh independent evidence for the same fixed terms, persists the claim, then reveals one unsigned action. The SDK binds its payload digest before invoking the wallet. Active lookup recovers a lost prepare response. Unknown signing/broadcast outcomes retain the wallet reservation; there is no automatic retry, repricing or resetting of an ambiguous action. Only neverclaimed READY plans can cancel or expire safely.

For the supported Base recipe, independent verification binds the original hash to the exact sender, router call, value and chain, requires at least 12 canonical confirmations, and checks recipient USDC credit against the reviewed minimum. Only a canonical reverted transaction proof permits terminal FAILED; pending or ambiguous evidence stays reserved. Persisted receipts include actual native fees and destination credit. Lifecycle timestamps are server observations, not exact wallet broadcast or settlement RTT. Relay cross-chain completion additionally requires independently verified finalized Solana recipient credit. Other provider routes and composed cross-chain paths remain pricing-only.

`await createFileExecutionStore({directory,maxRecords?,maxRecordBytes?,maxStoreBytes?})` implements `insert`, `get`, `findActive`, `compareAndSwap` and `close`. Pass it with the trusted engine to `createRouterApi`. Original approved requests, plans, review hashes and submitted hashes are immutable; an active source wallet is reserved across apps. Original transaction hashes stay unique per chain across retained history. Capacity refuses new records rather than evicting history.

Use a dedicated owner-only directory on a single POSIX host; symlink/hardlink and unsafe permission checks fail closed. One writer holds an exclusive persisted lock. Snapshots use temporary-file fsync, atomic rename and directory fsync. A crash or uncertain write leaves the lock and requires operator recovery; no automatic stale-lock removal is provided. After verifying that no writer remains and validating/reconciling persisted state against canonical chain evidence, an operator can clear the exact stale `writer.lock` and reopen. Never erase the snapshot or retry an ambiguous wallet action to recover a lock. The checksum detects accidental corruption; it is not authentication against a malicious filesystem owner. Multi-host coordination and durable backups remain deployment responsibilities.

Install the small standalone workspace dependencies before building; the server pins `viem` 2.56.3 for wallet signature verification. Local startup opts in with an owner-only `ROUTER_EXECUTION_PINS_FILE` containing the reviewed Base deployment pins. `ROUTER_EXECUTION_STORE_DIR` defaults to `.dev/executions`. Without pins, startup remains pricing-only. See the [root setup](../../README.md) and [deployment evidence](../../docs/validation/2026-10-09-base-execution-deployments.json). No live trade or public production readiness is asserted by these docs; Instinct integration remains off.
